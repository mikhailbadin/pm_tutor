# Тренажёр планирования релиза

Одностраничное офлайн-приложение: вы проходите шесть спринтов вымышленного релиза
«Онбординг 2.0» и в конце получаете посчитанный разбор — успели ли вы к дедлайну, куда ушла
ёмкость команды и что дала бы дисциплина.

## Зачем

Три вещи, которые обычно обсуждают словами, здесь видно в днях:

1. **Оценка задач.** Оценка не ускоряет работу — она делает план точнее. Без оценки в план
   попадает одна оптимистичная цифра (0.7 от реальности), а факт тянется из широкого
   распределения: разница оседает в переносах.
2. **Скоуп.** «Взять» ≠ «взять со обменом» ≠ «отложить» ≠ «отказать». Объём работы уменьшает
   только отказ; отложенное возвращается и сдвигает дату, а обмен сдвигает её не меньше,
   просто иначе.
3. **Техдолг.** Каждый непогашенный спринт — это минус скорость сейчас и минус качество после
   релиза. Долг платится временем, а время ограничено дедлайном.

## Запуск

Открыть файл двойным кликом: `dist/planning-tutor.html`. Ничего устанавливать не нужно —
ни зависимостей, ни сети.

Собрать заново (после правок в `src/`):

```bash
node scripts/bundle.mjs
```

Режим разработки (ES-модули, без сборки):

```bash
python3 -m http.server 8000 --bind 127.0.0.1   # затем http://127.0.0.1:8000/index.html
```

## Тесты

```bash
node --test
```

91 проверка, без единой внешней зависимости (`node:test`). Покрыты: арифметика последствий,
переносы работ, атрибуция потерь, сходимость обещанного с доставленным и остатком, Монте-Карло,
рендер экранов как строк, проводка кликов через фейковый DOM, блокировка спринта до решения
по входящим, сборка одного файла (включая проверку синтаксиса через `vm.Script`) и приёмочная
таблица стратегий. CSS и настоящие клики проверяются в headless-Chrome (сценарий из шести
спринтов прогоняется харнессом с реальными событиями мыши), в `node --test` они не входят.

## Сценарий и калибровка

24 задачи (202 дня правды) и 12 внеплановых событий (74 дня) против 240 человеко-дней ёмкости.
Запас — 38 дней: в план впритык не влезает ни одна внеплановая задача. Это и есть посылка
«успеем к релизу» — проверяется тестом `tests/scenario.test.js`.

Контрольные прогоны (`node --test tests/strategies.test.js`):

| Стратегия | Работа сделана | Ёмкость израсходована | В никуда | Осталось в скоупе | P(успеть) |
|---|---|---|---|---|---|
| Не оценивали, брали всё | 95.0 | 219.9 / 240 | 124.9 | 133.7 | 0% |
| Оценили, но брали всё | 147.8 | 219.6 / 240 | 71.9 | 123.0 | 0% |
| Оценили, отказывали во внеплане | 199.2 | 229.2 / 240 | 30.0 | 0 | 100% |
| Оценили, но откладывали внеплан | 199.2 | 229.2 / 240 | 30.0 | 74.0 | 0% |
| Оценили, но выменивали внеплан | 175.3 | 205.3 / 240 | 30.0 | 98.0 | 0% |
| Не оценивали + овертайм | 72.4 | 211.9 / 240 | 139.5 | 154.0 | 0% |

Сравните строки 3, 4 и 5: работы сделано почти столько же, потерь столько же — но у отказа
в скоупе ноль дней, у отложенного 74, у выменянного 98. Отложить и выменять — это не отказ,
просто релиз сдвигается. Каждое число проверяется тестом `tests/strategies.test.js`, который
вдобавок требует, чтобы обещанное сходилось с доставленным плюс остатком.

## Структура

```
src/engine/   чистая логика: ГПСЧ, оценки, арифметика потерь, исполнение спринта, разбор
src/data/     сценарий (данные, не логика)
src/ui/       состояние -> HTML-строка
src/app.js    единственное место с DOM
scripts/      сборка одного html-файла
tests/        node --test, без внешних зависимостей
```

Все числа воспроизводимы: seed сценария фиксирован, ГПСЧ детерминирован, порядок потребления
случайных чисел зафиксирован приёмочным тестом. Изменили механику — перемерьте таблицу выше
и обновите `EXPECTED` в `tests/strategies.test.js` (а не наоборот).
